## 2. Discussions & Updates

**Project Mode of Communication**
- Project communications will be conducted via Slack.
- Slack tools/apps to be integrated: Semgrep, GitHub Organization.
- Only Owners can set Rules on the GitHub Organization, thus accessibility is limited for other members.

**Roles Assignment**
- The Team Leader will assign a role responsible for merging branches, and members to work on specific folders.
- Two main role tracks discussed: Front End & Back End.
- Recommended role groupings:
  - **Leadership, Contract, and Integration:** Nietzchan, Raniel, Eulo
  - **Schema, Curriculum, and Business Rules:** Nietzchan, Raniel, Polo, Jerome, Matthew
  - **Auth, RLS, and Identity/Assignment Integrity:** Nietzchan, Raniel, Cyril
  - **Student and Adviser Portals:** Eulo, Cyril, John Earl, Ron
  - **Admin Portal and Reference Management:** Matthew, Polo, Mhac, Cyril
  - **Quality and Documentation:** Ron, John Earl, Mhac, and all feature owners

**Development Standards**
- All front-end development should use Context API, as suggested by the instructor.
- Jest and Vitest libraries will be used for unit testing.
- CI/CD workflow has already been set up by the Team Leader.
- The Team Leader has already prepared the following `.md` templates: `bug_report.md`, `task.md`, `test_case.md`, and `pull_request_template.md`.
- Detailed documentation will be maintained for version control.

**Project Milestones** (see README.md for full details)
1. Milestone 1: Foundation and Academic Model
2. Milestone 2: Advising and Enrollment Rules
3. Milestone 3: Exceptions and Administration
4. Milestone 4: Hardening and Release Readiness

**Project Management Tool**
- Kanban from GitHub Projects will be used to visualize project status and limit work in progress.
- The Team Leader will check whether Kanban can be integrated with Slack.

**GitHub Branching (strictly to be followed)**
- Permanent Branches: `Staging`, `Dev`, `Main`
- Other Branches: `feat/`, `fix/`, `contract/`, `db/`, `test/`, `docs/`
- `fix/` and `docs/` branches are open to everyone — role must be indicated in the branch name (e.g., `fix/db/` for fixing database seeding, etc.)
- `contract/` branch is exclusive to the Project Lead.
- `feat/` branch is for Front End.
- `db/` branch is for Back End.
- `test/` branch is for QA.

## 3. Decisions Made

- **Decision 1:** Project communications will be conducted through Slack, with Semgrep and the GitHub Organization integrated as tools.
